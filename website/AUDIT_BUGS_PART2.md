# Website audit — Batch 2 (2026-10-15)

## Scope and coverage

Only `website/` was inspected. No application code, migrations, commits, or remote state were changed. This report is the sole output file. The audit corpus is 433 TypeScript/TSX files under `src`, `middleware.ts`, `package.json`, `package-lock.json`, `next.config.js`, `tsconfig.json`, and the two website SQL migrations: **440 files read of 597 tracked website files**. The other tracked files are mainly assets, prior documents, scripts and config outside that corpus. All 27 `route.ts` handlers were inspected. Automated searches covered all 433 source files; detailed manual review concentrated on routes, auth, payments, Supabase reads, learning and resume flows. This is static evidence, not a live integration test.

## Auth, queries and UI checks

- Account protection: `requireUser()` is called by `account/layout.tsx:9-13`; onboarding checks session directly (`onboarding/page.tsx:17-26`). `safeInternalPath` rejects external, protocol-relative and backslash targets (`src/lib/nav.ts:8-14`). No open redirect was confirmed in these checks.
- Login/register/forgot/reset/verify-email/OAuth/logout paths were inspected at page and component level. The OTP routes use provider verification, and the reset form reports provider errors. Live email delivery, session expiry and OAuth redirect allowlists are **UNVERIFIED**; verify with real test accounts and Supabase Auth settings.
- Query inventory: 59 distinct `.from()` names (including the Storage bucket `custom-project-uploads`) and 49 distinct `.rpc()` names were found in source. The two website migrations define only contact form storage/RPCs, so all other table/column names, indexes and RLS policies are **UNVERIFIED from `website/` alone**. To verify, compare against the deployed Supabase catalog (`information_schema`, `pg_policies`, `pg_proc`) and run anon/user A/user B role tests. No `.select('*')` call was found in source; `jobs` detail uses `select("*, company:...")` at `src/lib/cache.ts:330`, so narrow that row to displayed columns. Several account pages use bounded lists with no pagination (wallet 50, purchases 100); the wallet balance defect is BUG-02. No service-role key use was found in source.
- Public visibility: jobs lists use `onlyActiveJobs` (`src/lib/jobsActive.ts:13-18`); blog uses published status (`src/lib/blog.ts:20-26`); learning RPCs claim publish/platform checks (`src/lib/learning.ts:24-31`) but live RPC definitions are outside scope. Project publish filtering remains BUG-12.
- Rendering: Markdown builds React text nodes and checks link schemes (`src/components/learning/Markdown.tsx:15-31`); no raw HTML injection was confirmed there. The remaining `dangerouslySetInnerHTML` sites are JSON-LD, static theme bootstrap and Prism-highlighted code; Prism is the one to recheck if highlighting inputs change. Static literal `href`/`action` route scan found no missing route. No general TODO/FIXME/HACK implementation markers were found. `Coming soon` states occur for empty Premium plans (`src/app/premium/page.tsx:126-130`) and referral terms (`src/app/referral/page.tsx:69`). Live catalog data controls whether those are placeholders in production.
